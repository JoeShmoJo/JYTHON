    01Everyday one-liners

    The blocks you will use nearly every time. Hit Copy, paste into PowerShell, press Enter.

    Save my work and put it on GitHub

    Change the text in quotes to describe what you actually did.

    git add . && git commit -m "describe what I changed" && git push
    noteThe && chain needs PowerShell 7+. Check with $PSVersionTable.PSVersion. On Windows PowerShell 5.1 replace each && with ; — but ; runs the next command even if the one before it failed.

    Get the latest version from GitHub

    git pull

    Where am I and what changed?

    git status && git log --oneline -10

    Brand-new repository, start to finish

    Run this inside your project folder, after making an empty repository on GitHub. Replace the URL.

    git init
git add .
git commit -m "initial commit"
git branch -M main
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main

    Copy an existing repository onto this PC

    cd C:\Projects\A_REPOSITORIES
git clone https://github.com/USERNAME/REPOSITORY.git

    Bin my local changes and match GitHub

    dangerThis permanently discards uncommitted work. Run git status first and read the list.
    git restore . && git pull

    02One-time setup

    Once per computer, then never again.

    Is Git installed?

    git --version

    No version number? Install it, then close and reopen PowerShell so the new PATH is picked up.

    winget install --id Git.Git -e

    Tell Git who you are

    Every commit is stamped with this. Use the email on your GitHub account.

    git config --global user.name "Your Name"
git config --global user.email "you@example.com"

    Defaults worth setting

    git config --global init.defaultBranch main
git config --global pull.rebase false
git config --global core.autocrlf true
git config --global credential.helper manager
    SettingWhy
    init.defaultBranch mainNew repositories start on main, matching GitHub — no more git branch -M main.
    pull.rebase falsegit pull merges rather than rebases. Simpler and safer when you work alone.
    core.autocrlf trueHandles Windows vs. Unix line endings, so files stop showing up as entirely rewritten.
    credential.helper managerWindows remembers your GitHub sign-in instead of asking on every push.

    Signing in

    Your first git push opens a browser window; sign in there and Windows stores the credential. Your GitHub password will not work at the prompt — GitHub stopped accepting it. If a terminal prompt ever asks for a password, paste a Personal Access Token instead (GitHub ▸ Settings ▸ Developer settings ▸ Tokens).

    git config --global --list

    03Create a new repository

    Local project folder in hand, empty repository waiting on GitHub.

    warningDo not tick Add a README, .gitignore, or license when creating the GitHub repository — each makes a commit your PC does not have, and your first push gets rejected. Already ticked one? Don't start over: run git pull origin main --allow-unrelated-histories before the first push.

    1 — Open PowerShell in the project folder

    cd C:\Projects\A_REPOSITORIES\Ephemeral
    tipFaster: open the folder in File Explorer, Shift+right-click the empty space ▸ Open PowerShell window here. Or type cd and drag the folder onto the window.

    2 — Initialise the repository

    git init

    This creates a hidden .git folder. That folder is your repository — the history lives there, not on GitHub.

    3 — Stage everything

    git add .

    The . means "this folder and everything under it". Staging is you saying these are the changes I want in the next snapshot.

    4 — First commit

    git commit -m "initial commit"

    5 — Name the branch main

    git branch -M main

    6 — Point it at GitHub

    origin is just a nickname for the URL.

    git remote add origin https://github.com/JoeShmoJo/Ephemeral.git

    7 — Push

    git push -u origin main

    -u links your local main to GitHub's, so plain git push and git pull know where to go from now on.

    Memory aid: init → add → commit → branch → remote → push

    Wrong URL?

    git remote -v
git remote set-url origin https://github.com/USERNAME/REPOSITORY.git

    04The everyday workflow

    Once the repository exists, this is the whole job: add → commit → push.

    git status                              # what changed?
git add .                               # stage all of it
git commit -m "describe what I changed" # snapshot it locally
git push                                # send it to GitHub

    Staging only some files

    git add notes.md src\main.py
git commit -m "update notes and main script"

    A commit message worth reading

    Finish the sentence "If applied, this commit will…". Present tense, under about 60 characters, says what and why.

    GoodNot so good
    add retry logic to the download stepfixes
    fix crash when the input file is emptyupdate
    rewrite README install instructionsstuff

    A commit is a local save point and costs nothing — make them small and frequent. A push is a backup. There is no penalty for pushing ten times a day.

    05Pulling, and conflicts

    Five situations cover essentially every sync problem you will hit working solo across two machines.

    1 — Normal update

    git add . && git commit -m "describe what I changed" && git push

    2 — Push rejected because GitHub has changes

    GitHub has commits your PC does not — you edited on the website, or pushed from another machine. Git says "Updates were rejected because the remote contains work that you do not have locally." Bring them down first:

    git pull && git push
    noteThis is not an error you caused. It is Git protecting the commits already on GitHub.

    3 — The pull produced a merge conflict

    Git could not decide which version of a line to keep, so it is asking you. Nothing is broken and nothing is lost. First, see which files:

    git status

    Open each one. You will find markers like this:

    <<<<<<< HEAD
your local version of the line
=======
the version that came from GitHub
>>>>>>> origin/main

    Edit the file so it reads the way you want — keep one side, keep both, or rewrite it. Then delete all three marker lines and save. Finally:

    git add . && git commit -m "resolve merge conflict" && git push
    tipCatch leftover markers before committing with git diff --check, or search the folder for <<<<<<<. Want out entirely? git merge --abort puts you back exactly where you were before the pull.

    Memory aid: pull → resolve → add → commit → push

    4 — Discard my changes, take GitHub's version

    dangergit restore . throws away uncommitted edits to tracked files. They are not recoverable.
    git status
git restore . && git pull

    5 — Also delete untracked files

    git restore . never touches files Git has not seen. To clear those too — preview first, -n means "show me, don't delete":

    git clean -fdn

    Read that list carefully. If it is right:

    git clean -fd && git pull
    dangergit clean -fd permanently deletes untracked files and folders. No undo, no Recycle Bin.

    Not ready to commit, but need to pull

    git stash
git pull
git stash pop

    06Undo: the safety net

    Almost everything is reversible once it has been committed. That is the real reason to commit often.

    I want to…Command
    Undo edits to one filegit restore path\to\file
    Undo all uncommitted editsgit restore .
    Unstage a file, keep the editsgit restore --staged path\to\file
    Fix the last commit messagegit commit --amend -m "better message"
    Add a forgotten file to the last commitgit add forgotten.txt && git commit --amend --no-edit
    Undo the last commit, keep the changesgit reset --soft HEAD~1
    Undo the last commit and its changesgit reset --hard HEAD~1
    Get one file back as GitHub has itgit checkout origin/main -- path\to\file
    Reverse an old commit safelygit revert COMMITHASH
    See everything I have done recentlygit reflog
    warningNever --amend or reset a commit you have already pushed — that rewrites history GitHub already has, and your next push is rejected. To undo something already on GitHub, use git revert, which adds a new commit that cancels the old one.

    When you have really made a mess

    git reflog lists every position HEAD has held, including commits you thought you destroyed. Find the line you want, take its short hash, go back:

    git reflog
git reset --hard a1b2c3d   # the hash from the line you want

    07Branches

    A parallel line of work. Try something risky on a branch and main stays untouched. Optional when you work alone — and the cheapest safety net there is.

    git switch -c experiment      # create one and move to it
git push -u origin experiment # first push needs the -u
git branch                    # list branches, * marks the current one
git switch main               # move back

    Merge the work back into main

    git switch main
git pull
git merge experiment
git push

    Delete a branch you have finished with

    git branch -d experiment              # local
git push origin --delete experiment   # on GitHub

    08.gitignore

    A list of things Git should never track: secrets, build output, huge data files, editor cruft. It sits in the top folder and should be committed.

    Write a starter file

    @"
# Windows
Thumbs.db
desktop.ini

# Editors
.vscode/
.idea/

# Python
__pycache__/
*.pyc
.venv/

# Node
node_modules/

# Secrets - never commit these
.env
*.key

# Big / generated stuff
out/
*.log
"@ | Set-Content -Encoding utf8 .gitignore
    noteThat @" … "@ is a PowerShell here-string. The closing "@ must sit at the very start of its own line or PowerShell complains.

    I already committed something that should be ignored

    Adding it to .gitignore is not enough — Git keeps tracking files it already knows. Untrack it but keep the file on disk:

    git rm --cached secrets.env
git commit -m "stop tracking secrets.env"
git push
    warningIt is gone from future commits but still in the history. If the repository is public, treat any leaked key or password as compromised and rotate it.
    git check-ignore -v path\to\file   # why is this ignored?

    09PowerShell gotchas

    Paths with spaces need quotes

    cd "C:\Users\Me\My Projects\Ephemeral"

    Chaining commands

    OperatorBehaviour
    &&Runs the next command only if the previous one succeeded. PowerShell 7+ only.
    ;Runs the next command regardless of failure. Works everywhere.
    $PSVersionTable.PSVersion                        # which PowerShell is this?
winget install --id Microsoft.PowerShell -e      # get version 7

    Quoting commit messages

    Single quotes are safest — double quotes let $ expand into a variable.

    git commit -m 'fix the $HOME lookup'   # literal text, safe
git commit -m "fix the $HOME lookup"   # PowerShell substitutes $HOME first

    OneDrive and cloud folders

    dangerA repository inside OneDrive, Dropbox, or Google Drive causes real corruption — two sync engines fighting over the same .git folder. Keep repositories somewhere local like C:\Projects and let GitHub be the backup.

    Stuck in an editor or a pager

    Ran git commit with no -m and landed in Vim? Press Esc, type :wq, press Enter. Screen full of log output with a : prompt? Press q.

    git config --global core.editor "code --wait"
git --no-pager log --oneline -20

    10The danger zone

    Four commands can actually destroy work. Everything else in Git is recoverable.

    CommandWhat it can cost you
    git push --forceOverwrites commits on GitHub. Every other copy — including your other PC — breaks. Never reach for it to fix a rejected push; git pull is the answer there.
    git reset --hardDeletes uncommitted work with no prompt. git reflog rescues committed work only.
    git clean -fdDeletes untracked files and folders. No Recycle Bin. Preview with git clean -fdn first.
    git restore .Discards every uncommitted edit to tracked files.
    dangerBefore any of those, run git status and read it. If you are unsure, commit first — an unwanted commit costs nothing and makes the change undoable.

    11Error messages, decoded

    Git saysYou do
    Updates were rejected because the remote contains work that you do not have locallyGitHub is ahead of you. git pull, resolve anything it asks about, then git push.
    fatal: not a git repositoryWrong folder, or you never ran git init. cd to the project folder.
    fatal: remote origin already existsAlready set. Repoint it: git remote set-url origin URL.
    src refspec main does not match anyNothing committed yet. git add . then git commit -m "initial commit".
    Please tell me who you areSet user.name and user.email — see One-time setup.
    Support for password authentication was removedUse the browser sign-in window, or a Personal Access Token instead of your password.
    Your local changes would be overwritten by mergeCommit them, or git stash → git pull → git stash pop.
    nothing to commit, working tree cleanNot an error. Nothing has changed since your last commit.
    detached HEADYou are looking at an old commit, not a branch. git switch main puts you back.
    error: pathspec … did not match any fileTypo in a filename or branch name. git status and git branch show the real ones.

    12Command index

    CommandDoes what
    git statusWhat changed, what branch, what to do next
    git add .Stage every change in this folder and below
    git commit -m "msg"Snapshot the staged changes locally
    git pushSend commits to GitHub
    git pullBring GitHub commits down and merge them
    git clone URLCopy a GitHub repository onto this PC
    git initTurn this folder into a repository
    git remote -vWhich GitHub repository is this linked to?
    git log --oneline -10Last ten commits, one line each
    git log --oneline --graph --allVisual history including branches
    git diffWhat you changed but have not staged
    git diff --stagedWhat you staged but have not committed
    git show COMMITHASHEverything one commit changed
    git branchList branches
    git switch -c NAMECreate a branch and move to it
    git merge NAMEMerge a branch into the current one
    git stashPark uncommitted changes
    git stash popBring parked changes back
    git restore FILEUndo uncommitted edits to a file
    git revert COMMITHASHNew commit that undoes an old one
    git reflogEvery recent position of HEAD — the rescue tool
    git rm --cached FILEStop tracking a file, keep it on disk
    git config --global --listShow your global settings
