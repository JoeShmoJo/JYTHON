Upon Restart

  1. Back up the complete existing watershed and any study forecasts/results you intend to retain. Preserve this embedded kit and original-source folders.
  2. Read scripts/workflow-mode.json; compare it with the environment you intend to use. It records installation mode, not automatic GUI detection.
  3. Verify the original HEC application and the hydro39 Python environment. Use the inventory to identify dependencies and versions. Recreate/install them through approved channels if the old machine/environment is gone. The kit does not bundle Conda, Python packages, HEC applications or authentication.
  4. If changing mode, close both applications and use the embedded installer as described in WORKFLOW_PACKAGE.md. Activate RTS mode only in the imported copy.
  5. Open the environment's launcher. Verify target, dates, paths, trial convention, inputs and native rule bindings before changing or computing anything.
  6. Preserve existing results. Run a small serial baseline, verify initialization receipts and native completion, then validate outputs before a large study.
  7. Record local test findings and changes in PROJECT_LOCAL_NOTES.md. Keep an example successful log and the exact configuration used with study results.

POR and model checks

Single POR / Model Check documents the mode toggle, OSI-free single-run plotting and launching the existing model checker for one POR output or one exact ensemble member. Native mode/input settings are not changed by the toggle.

Optional follow-up experiment

Conditional diversion postprocessing reads completed results and writes separate adjusted flows. It is opt-in, not part of the accepted baseline/augmentation workflow. Review its routing/barrier assumptions and test locally before use. The editor can also add inactive IRRM/Deep Drawdown reservoir settings; native rule attachment still requires the ResSim editor.

Known issues to carry forward

  • Some optional FLOW-MINLIM archive reads contain no usable values. Actual native

values versus reader behavior remain unresolved; see the next-session checklist.

  • RTS baseline identity compares pool elevation/outflow, not every input. An

input-only edit can retain an old archive when compared outputs are unchanged. Use a fresh forecast for a clean input-change experiment until this is resolved.

  • Old output records can look successful after a failed compute. Check current

logs, selected members and full time coverage; 100% alone is insufficient.

  • Standalone Apply does not turn off augmentation or change native trial settings.
  • Peak CSV cleanup is not a full-series archive suitable for augmentation.
  • No season offered in RTS means required baseline coverage is unavailable.
  • Parallel scripted ensemble support depends on the original application; the

package neither repairs nor enables it through vendor software modifications.
