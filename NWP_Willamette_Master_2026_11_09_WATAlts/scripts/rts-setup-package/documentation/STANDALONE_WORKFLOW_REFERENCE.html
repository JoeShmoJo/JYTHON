Standalone and shared workflow: technical and data reference

Version: 16 October 2026. This documents the packaged implementation and the reviewed legacy scripts. Actual installed code can differ; use the package's installation inventory and printed job paths to resolve differences. The kit does not automatically inspect or certify embedded native scripts/mappings.

Simulation, native alternative, trial, historical ensemble member and RTS forecast alternative/run code are different identifiers. In standalone, the browser menu requires a simulation folder and alternative name explicitly. It does not detect the active GUI selection. The command-line editor requires --simulation and --alternative as well. Menu jobs use the same selected target and the applied standalone_workflow settings in the baseline snapshot. The shared CONFIG.py is not read; the remaining OSI option has an explicit default in the browser until reviewed and applied. A simulation with spaces is normalized to underscores by the backend. Output DSS is used to locate the active pointer at compute initialization. The runtime also checks the native alternative name before applying overrides.

Legacy alternative defaults are read first, then the alternative's settings. The editor imports those and the preserved rule constants/tables into a reusable set. Once applied, scoped snapshot overrides are used for the matching simulation and alternative; other alternatives retain legacy behavior. Within that simulation, all trials of the selected alternative receive the applied baseline settings. Only one selected alternative is bound by the active pointer in a simulation; the editor refuses opening that pointer as a different alternative.

The current menu uses no shared CONFIG.py file. It supplies simulation, alternative and applied osi_source_member through a private temporary legacy compatibility module. Other hardcoded date/member controls remain in individual scripts. The older standalone plot scripts described below are retained as legacy manual tools; the current menu uses named saved results.

Inactive reservoir slots

IRRM and Deep Drawdown configurations include all 13 reservoirs. Existing values and activation flags are preserved; missing entries have false activation and null targets/seasonal fields. They display as blanks and do not add native rules. An off switch or missing required setting makes that reservoir's rule neutral, even if its switch is on. The browser shows Off, Not configured, or On and the resolved snapshot records operating_status. Complete enabled entries operate normally. Off/incomplete Deep Drawdown rows are excluded from runtime CSVs; IRRM masks an incomplete target inactive before interpolation. Invalid nonblank numbers/dates still fail validation. Opening older sets expands only the editable view; Save/Apply makes a new version without rewriting historical library/applied files. Linked CSV bytes stay unchanged; missing editable slots appear after resolving/saving them inline.

Baseline settings: outputs and consumers

The shared editor covers DeepDrawdown, SpringSpill, NoDraft, SecondaryFloodDraftLimit, FIRO_SPACE, MinFlowPlusWithdrawal, DiversionFromCSV, IRRM, DraftToRC, FillLOPfirst and HCR_LOP_Balance. Diversions can be negative returns; the diversion/withdrawal enable settings must agree with the intended Combined Min Trib behavior. The editor controls scripted settings, not whether native rule objects exist or are bound in every operation set.

Receipts record ensemble member when recognized, otherwise null plus output F-part for a non-ensemble run. They prove initialization, not success or freshness of all computed data. Reviewed augmentation code uses CONFIG.SIM_NAME and ALTERNATIVE_NAME_STEP1; menu jobs supply these from the selected target through a private temporary compatibility module. The calculator reads/writes the same simulation.dss, has a 10-day short horizon, and uses April 1–October 31 season constants. It derives full-series inputs including storage/flows/requirements and writes FLOW-MIN-EXTERNALFLOWAUG and diagnostic Salem/Albany requirement/deficit variants. Inspect actual printed paths and DSS F-parts: the exact trial/member suffix selection remains model-specific. Recalculate after changing baseline results or augmentation parameters. The standalone button does not create RTS scheme manifests or immutable result pairs.

Reviewed standalone plot F-parts normalize spaces to hyphens, pad short alternative names to ten characters, then append the trial suffix. A native output may use a different spelling/case; inspect real paths when no plots appear. Reviewed HTML uses Plotly CDN assets, so do not assume these standalone plots work offline. RTS saved-run plots embed/copy their offline library separately.

Native PostProcess_CSV cleanup is a different path: ensemble cleanup can append PeakExtract_<alternative>.csv beside the output DSS; non-ensemble cleanup can write <alternative>.csv.gz. The embedded cleanup script determines actual fields and behavior. Peaks cannot substitute for daily ensemble series in augmentation. The kit does not modify cleanup bindings or reduce native DSS output volume.

Mode conversion and installed-source provenance

RTS mode installs the maintained RTS backend/extraction helpers, RTS launchers, rts_baseline_runtime and RTS MainstemFlowAugSV. It unwraps recognized standalone rule adapters and preserves neutral original sources before adding RTS wrappers. Standalone mode performs the reverse adapter change and restores previously preserved standalone helpers/state variable. Newly added RTS-only helper files can remain dormant; use the correct launcher for the installed mode.

Backups preserve existing affected files; entries marked absent were newly installed. Restore existing entries and remove only newly created entries to undo an installation. Installation failure rolls back its script writes. Keep backups until both workflows are locally validated. The first preserved standalone helper copies are not a live synchronization mechanism: later custom helper edits need explicit review when updating or switching modes. Do not edit kit sources and installed sources independently without recording which is authoritative.

RTS acceptance/schemes/compact arrays are documented in RTS_WORKFLOW_REFERENCE.md. Key distinction: reusable JSON can cross environments; result identities and active pointers do not. Apply JSON to the new target, compute and accept anew.

Preservation and recovery

Retain the full model, embedded scripts, original-source folders, CSVs, saved libraries, needed simulation DSS files, forecast inputs, applied snapshots and RTS archives. Keep native model alternative/operation bindings and application version information. Compact primary series.npz files are study data, not caches. Do not delete the only primary arrays or source data when cleaning up.

The inventory records the packaging interpreter and installed distribution versions without exporting credentials. It is a dependency record, not a Conda lockfile or environment installer. DLL/native DSS compatibility and CWMS access must be validated separately. Credentials and machine trust settings are outside the watershed. Use approved storage/access procedures for those.

A clean restart test uses preserved inputs and a small serial case, known saved settings, current log completion and verified member/date coverage. Compare actual reservoir outflows and Salem flows (and elevations as relevant) against a preserved reference. Exact matches support that case; they do not prove every future member, time window or native script path behaves identically.
