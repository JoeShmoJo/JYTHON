Standalone and RTS workflow package

This kit travels with the watershed at scripts/rts-setup-package. It contains both menus, the baseline editor/runtime, RTS extraction/augmentation/archive/plot helpers, script installers, and the operator/file reference documents. manifest.json contains SHA-256 checksums of the kit payload. No application JAR, Java runtime, Python environment, DSS output or model network is bundled by this kit.

Keep the existing watershed scripts, CSVs, alt_config, external modules, native alternatives and DSS mappings when transferring the watershed. The kit supplements those model-specific files; it is not a replacement watershed or a universal model installer. Keep the standalone watershed and imported RTS copy separate.

Read in a browser

Double-click WORKFLOW_README.html at the watershed root. The linked HTML guides under scripts/rts-setup-package/documentation work offline with navigation, formatted tables and code, and browser printing/PDF export. No server, Markdown viewer or additional Python package is needed to read or generate them. Editable Markdown is grouped in documentation/sources; users read HTML. Open scripts/START-HERE.html or documentation/index.html. Rerunning the embedded packager regenerates HTML.

The standalone menu also supports Single POR / Model Check. The embedded model_check directory contains code/limits only; native results and old report output folders are not copied into the kit.

Standalone SOP

  1. Finish compute and close ResSim before installing/updating scripts.
  2. Reopen the watershed in standalone ResSim. In the Simulation module Script Editor, run the launcher below. Select the actual simulation folder and alternative.
  3. Open Baseline Configuration, verify the target banner, load/import/edit settings, save a named configuration, then Apply. Compute manually in ResSim.
  4. Use existing native standalone augmentation conventions, then archive/plot named results using saved-run instructions. The other menu jobs use the selected target and applied Standalone job settings in the baseline editor. Apply before extraction/calculation jobs. Plotting existing archives needs no new Apply. Verify additional downloader/date constants and native mappings separately. Apply does not turn off standalone augmentation automatically.
  5. See standalone instructions for validation, trial conventions, receipts and rollback. The user has verified standalone configuration in ResSim; new environment transitions still need local testing.

Standalone Script Editor launcher:

from hec.script import ClientAppWrapper; import os; execfile(os.path.join(str(ClientAppWrapper.getWatershed().getWkspDir()), 'scripts', 'STANDALONE_WORKFLOW_MENU.py'))

Import into RTS

Use the fresh-import validation checklist for the next local test. The latest end-to-end native import remains unverified.

  1. Import/copy the complete watershed using your normal RTS import procedure. Confirm scripts, rts-setup-package, native alternatives and DSS mappings survived.
  2. Close RTS and ResSim. Activate RTS mode in the imported watershed copy, before creating a new forecast. Run the following line and enter that copy's watershed root, not a forecast root or your standalone source.
$ws = Read-Host "Imported RTS watershed root"; & "$env:LOCALAPPDATA\miniconda3\envs\hydro39\python.exe" (Join-Path $ws "scripts\rts-setup-package\Install-StandaloneConfiguration.py") --watershed $ws --mode rts
  1. Reopen RTS, verify imported model/program linking, create/select the forecast, and run scripts/RTS_WORKFLOW_MENU.py in the RTS Script Editor. Check forecast, run, DSS file, dates and timezone. Do not use the standalone menu in RTS.
  2. Initial Extract → configure/apply baseline → compute unaugmented → accept results → configure/process/load augmentation → compute augmented → accept/plot. Follow RTS operator SOP for the full sequence and file reference for inputs, outputs and provenance.
  3. Saved baseline JSON uses the same format in both environments. Open the saved set and Apply again in the new forecast. Standalone active pointers, simulation outputs and initialization receipts are not RTS baseline acceptance or archives. Native operation sets, mappings and standalone augmentation trials are not converted by loading configuration JSON. Validate these in the imported model.
  4. First run a small serial case and verify initialization and expected output. This package does not install the experimental Java/compiler modification or promise native multithreaded scripted ensemble support.

RTS Script Editor launcher:

from hec.script import ClientAppWrapper; import os; execfile(os.path.join(str(ClientAppWrapper.getWatershed().getWkspDir()), 'scripts', 'RTS_WORKFLOW_MENU.py'))

The existing hydro39 Python environment must be installed on the destination machine. The launchers expect %LOCALAPPDATA%\miniconda3\envs\hydro39\python.exe. Python needs the existing project dependencies including numpy, pandas, plotting packages and the working DSS binding. CWMS/RFC extraction also requires network access and CWMS access/certificates. These prerequisites are not installed by the kit. RTS metadata, program linking, valid forecast dates and model mappings still require normal RTS setup. Archived RFC loading remains outside this workflow.

Switching, backups and files

The mode installer unwraps recognized adapters using preserved original sources, then installs the selected adapter once. It refuses missing originals/unknown setup code before writing. It backs up every affected existing file and rolls back script writes if installation fails. Restart after switching to clear cached Jython modules. Never switch during compute or run both environments against the same writable watershed.

To switch a copy back to standalone, close applications and run the embedded installer with --mode standalone instead of --mode rts. CONFIG.py and all native model settings remain as they were; verify them before computing. To roll back a particular installation, use its printed backup and files.json: restore entries that existed and remove only newly installed entries. Mode switching retains both environments' saved/applied configurations; it does not migrate result data.

No CONFIG.py, alt_config file, user CSV schedule, native network, simulation DSS, forecast DSS or application JAR is rewritten by packaging/mode installation. RTS mode deliberately installs the maintained MainstemFlowAugSV implementation; standalone mode restores the preserved standalone implementation.

Refresh the portable package

Close applications and preserve local mappings before running this command in the standalone source. Packaging installs standalone mode; do not use it to refresh an active RTS copy. It preserves the previous kit and records a fresh inventory. It does not install HEC or Python.

$ws = Read-Host "Standalone watershed root"; & "$env:LOCALAPPDATA\miniconda3\envs\hydro39\python.exe" (Join-Path $ws "scripts\rts-setup-package\Package-Workflow.py") --watershed $ws

For a documentation-only refresh, run python scripts/rts-setup-package/render_documentation.py from the watershed root. Packaging refreshes WORKFLOW_README.html at the watershed root and START-HERE.html in scripts. Existing operator Markdown notes are preserved, not overwritten.
