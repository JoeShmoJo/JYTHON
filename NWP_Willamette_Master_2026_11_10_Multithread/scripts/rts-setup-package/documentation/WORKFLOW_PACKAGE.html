Portable watershed workflow: one opener for ResSim and RTS

The watershed already contains both runtime backends. Import the complete watershed into RTS using the normal HEC import process, then open scripts/OPEN_WORKFLOW.py. The existing scripts/STANDALONE_WORKFLOW_MENU.py entry is a compatibility alias for the same automatic opener. No installer command or workflow-mode switch is part of normal use.

Open the workflow

  1. In standalone ResSim, load the source watershed and open the GUI script.
  2. In RTS, open the imported watershed, create/open a forecast and select its run, then open the same GUI script.
  3. The opener checks for a running CAVI application frame. It launches the RTS UI in RTS and the standalone UI in standalone ResSim. Having CAVI classes on the classpath alone does not select RTS.
  4. Check the displayed target, dates, timezone and DSS path before extraction.

If a HEC Script Editor does not supply the script filename and the loaded watershed cannot be located through its application wrapper, the opener asks you to select the already-loaded watershed folder. This locates the bundled scripts; it does not install, copy, patch or switch any files.

The GUI opener does not modify workflow-mode.json, native alternatives, scripts, application JARs or data. The old mode marker is not used for automatic dispatch. Each environment keeps its own baseline pointers and initialization receipts. RTS uses the preserved native rule originals already shipped with the watershed.

Import and validate

Keep the standalone master and import a separate complete copy into RTS. Retain both ExternalPython and RTSPython, native modules, preserved originals, CSVs, model files and mappings. Importing only the maintenance kit is insufficient. Use the archive date/member check before extracting historical forecasts; native ResSim ensemble selection must match the requested years. Finish computes and close DSS views before confirming an extraction. Compute remains a manual HEC application action.

Python hydro39, its dependencies (including pyarrow for archives), HEC libraries and data-service access are still machine prerequisites. Automatic application routing does not install Python packages or validate a native RTS import. See RTS archived forecasts and fresh-import validation.

Maintenance and older copies

Package-Workflow.py can refresh the portable kit and pre-bundled RTS backend in a source watershed before distribution. Packaging no longer runs a mode-switch installer or rewrites model rule adapters. Ship the updated whole watershed.

The older Install-StandaloneConfiguration.py and PowerShell installers remain available for explicit repair/migration of older installations. They are not run by the opener and are not required after importing this bundled watershed.
