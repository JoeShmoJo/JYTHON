What works / intended design

The user has exercised the standalone configuration editor, Model Check and basic ensemble saved-result plots. Reference plotting was recently added and still has an open data-read issue below. The newest packaged model has not yet completed a fresh native RTS import validation.

Use one native alternative, changing named baseline settings through the menu rather than multiplying alternatives/trials. Save stores reusable configuration; Apply activates a snapshot for the selected target; native compute is manual. Archive completed baseline/results under descriptive names to compare later. Do not replace saved history with live DSS records when plotting.

  • Shared opener: scripts/OPEN_WORKFLOW.py in either application; the existing

STANDALONE_WORKFLOW_MENU entry is an alias. It detects the running host and selects ExternalPython for standalone or RTSPython for RTS. A separate local LAUNCH_WORKFLOW_GUI shortcut may call the opener with an explicit filename.

  • No installer or workflow-mode flag change is needed. Keep both backends with

the full watershed; never paste a launcher over RTS_WORKFLOW_MENU.py.

  • Shared baseline editor uses eleven rule groups and named portable JSON sets.

Inactive/null IRRM and Deep Drawdown entries are neutral; effects still require native rule attachment. Adding a reservoir to JSON does not attach a native rule.

  • Normal menus do not depend on a user-edited shared CONFIG.py. Older job scripts

receive a private temporary compatibility module. Keep legacy files intact.

  • POR can use augmentation and saved-result plotting. OSI applies only to ensembles.

The POR augmentation adapter supplies daily inputs from native blocks; subdaily flows use complete-day period averages, storage uses day-end values. Validate the calculation and native requirement mapping locally before study use.

  • Synthetic ensemble IDs: 3000/3001/3002 daily percentile traces; 3003 OSI. Old

files may use 2026–2029. Do not relabel those automatically or include synthetic traces in historical probability bands.

  • Model Check reads the selected POR output or exactly one ensemble member.

Optional report name; unique report directories. It does not start compute.

  • Native uppercase DSS names are supported by case-insensitive extraction/report

matching. Original DSS paths and values are retained.

Rules for resuming safely and efficiently

  1. Read this file, PROJECT_LOCAL_NOTES.md, the applicable SOP and the import checklist. Inventory actual files/mode before changing them. Do not assume another machine can access the Windows watershed directly.
  2. Reuse the existing test watershed for successive tests; it is large. Make a separate imported RTS copy for the transition, but avoid repeated whole-model copies for small script experiments. Preserve working source/configuration/data.
  3. Do not modify, decompile or recreate modifications to vendor JARs. Experimental compiler isolation was retired after review of HEC terms. The workflow uses original supported HEC applications and user scripts; Java experiments are not prerequisites. Do not infer thread safety from a successful serial run.
  4. Test installed modules in a fresh process, without project imports masking missing dependencies. An earlier archive failure was exactly that omission.
  5. Validate the delivered scripts and both auto-selected backends on a disposable project copy. Native Windows/DSS validation is separate from Python checks; record which checks actually ran and preserve their results.
  6. Python jobs use hydro39 at %LOCALAPPDATA%\miniconda3\envs\hydro39\python.exe; the GUI-side scripts are Jython. The kit does not provide Python packages, native DSS bindings, HEC, CWMS credentials/certificates or network access. Inspect existing prerequisites.
  7. Keep PowerShell commands on one line for the operator. Editing kit files alone never installs into the watershed. Repackage and reopen the menu to test delivered behavior. Import the complete bundled watershed and use the same opener in RTS; no activation installer is needed.
  8. Native output presence or 100% progress does not prove successful fresh compute. Verify selected member/time coverage and current logs. Record observed outcomes separately from automated tests and assumptions.

Historical RFC archive loading is available in both environments, with date/member checks and an explicit leap-day policy. Native RTS compute validation remains separate. The optional diversion postprocessor is a separate opt-in experiment with routing and reservoir-barrier limitations; it is not a substitute for native operating feedback.
